### 三、语音说到中途断掉（用户报障）
**根因**：Vivix 的 `response.create` 默认 `scheduling_policy: "interrupt"`。
她还在说的时候又来一条请求，就会把她那句拦腰切断 —— 答案越长越容易撞上，
正好对上用户说的「长句子容易遇到」。
**修法（客户端排队）**：
- 新增 `state.speaking` / `responsePending` / `answerQueue` / `userCancelled` / `speakingWatchdog`。
- `requestResponse()`：忙就 `answerQueue += 1`，否则发 `response.create`。
- `beginSpeaking()` 在 `response.created` / `response.render.started`；
  `endSpeaking()` 在 `response.done`，随即 `drainAnswerQueue()` 依次补发。
- 看门狗：只要有事件进来就重新计时，**真的 120 秒没动静**才兜底放行，避免队列卡死。
- 「打断」按钮仍即时 `response.cancel`，并置 `userCancelled`，不把它当故障报出来。
- **`response.render.stopped.status` 与 `response.done.status` 以前被静默吞掉**，
  现在非正常结束会在聊天里如实写一行（`reportResponseOutcome`）。
- 输入框回车补 `keyCode === 229` 判断，中文输入法选字不再误发消息。

**新坑 / 复现结论**
- **`git grep` 会把 GBK 文件当二进制跳过** → 靠它扫不全旧名，要用 Python 逐字节扫
  （`C:/Users/80573/.workbuddy/tmp/scan_names.py`）。
- **esbuild 的非 ASCII 转义是「大写」十六进制**：`\u8D5B\u535A\u604B\u4EBA`。
  我第一次用小写 `\u8d5b` 去查 exe，新旧文件都查不到中文，白白怀疑了半天。**记住大写。**
- **`.gitattributes` 缺失时 `core.autocrlf=true` 会把 `.cmd` 的 CRLF 规范成 LF 存进 blob**
  （这个仓库一直有这毛病，`install.cmd` / `启动.cmd` / `关闭.cmd` 全是 LF blob）。
  已加 `.gitattributes` 把 `*.cmd` 与 `installer/readme.txt` 标为 `-text`。
  ⚠️ **改完必须 `git add --renormalize`** —— 普通 `git add` 不会重新规范化已经在索引里的内容，
  我第一次就是这么被骗过去的（索引还显示旧字节）。
- **Git Data API 在完全空库上会 409 `Git Repository is empty`**，所有写入都被拒。
  先 `PUT /repos/{o}/{r}/contents/.init` 垫一个占位提交让仓库变非空，最后再 `PATCH /git/refs/heads/main`
  （`force: true`）覆盖过去，占位提交就变成不可达、自然消失。
- **`git diff --name-only` 会把中文文件名转义成 `"\345\205\263..."`** → 后续 `git show <sha>:<path>` 找不到文件。
  加 `-c core.quotepath=false` 解决。
- **本机 curl 打 GitHub raw 会挂**（不只是慢，是直接没响应），验证远端文件一律走
  `gh api .../contents/<path>` 看 `size` + 比对 blob SHA，别用 raw 域名。
